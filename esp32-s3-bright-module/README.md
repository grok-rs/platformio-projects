# ESP32-S3: «Яскравий модуль» — ТЗ-A модуля 2.2

Транзисторний ключ на **2N2222**: ESP32-S3 керує яскравістю LED, який живиться від окремого модуля
**MB-102 (+5 В)**. Апаратний ШІМ LEDC (5 кГц, 8 біт) на **GPIO5**, кнопка на **GPIO6** перемикає рівні
OFF (0) → LOW (40) → MID (128) → HIGH (255) → OFF. Теорія —
[«Потужне навантаження»](https://grok-rs.github.io/platformio-projects/power-loads/), завдання —
[ТЗ-A](../docs/power-loads/tz-a-spec.png).

```bash
cd esp32-s3-bright-module/cpp
pio run -e levels  -t upload && pio device monitor   # етап 4: кнопка + 4 рівні (за замовчуванням)
pio run -e switch  -t upload && pio device monitor   # етап 2: GPIO5 HIGH/LOW по 3 с
pio run -e sweep   -t upload && pio device monitor   # етап 3: ШІМ 0 → 255 → 0
pio run -e softpwm -t upload && pio device monitor   # рівень «+»: програмний ШІМ на millis()

cd esp32-s3-bright-module/rust
cargo run --release                                  # levels; --bin switch / sweep / softpwm
```

Один файл на етап: `cpp/src/{switch,sweep,levels,softpwm}.cpp` і `rust/src/bin/*.rs` рядок у рядок.

## Схема

![Принципова схема](docs/schematic.png)

![Монтаж на макетній платі](docs/breadboard.png)

```
+5 В MB-102 ── LED ── R2 220 Ом ── колектор ┐
                                            2N2222 (NPN, ключ «на землі»)
GPIO5 ── R1 1 кОм ─────────────────── база ┤
                                     емітер ┴── GND ══ GND ESP32 (спільна земля)
3V3 ── кнопка ── GPIO6                      (INPUT_PULLDOWN: відпущена = LOW, натиснута = HIGH)
```

**Розрахунок.** GPIO5 = HIGH: I<sub>Б</sub> ≈ (3,3 − 0,7) / 1 кОм ≈ **2,6 мА** — пін це легко дає.
Струм LED іде від MB-102: I<sub>К</sub> ≈ (5 − 2,0 − 0,1) / 220 ≈ **13 мА** (червоний LED). I<sub>К</sub> / I<sub>Б</sub> ≈ 5 ≪
h<sub>FE</sub> ≥ 75, тож транзистор у насиченні: U<sub>КЕ</sub> ≈ 0,1–0,2 В.

**Безпека.**
* R1 обов'язковий: перехід база–емітер — це діод, без резистора GPIO5 майже замкнений на GND.
* Спільна GND: струм бази повертається в ESP32 через емітер → GND. Без цього дроту ключ не відкривається.
  Це **єдиний** зв'язок між живленнями.
* +5 В MB-102 — лише до LED, ніколи до 5V/VIN/пінів ESP32. Кнопка — від 3V3, **ніколи 5 В у GPIO**.
* Схему перемикати лише при вимкненому живленні.

## Як це працює

ISR лише ставить `volatile`-прапорець (ВП-4), усе інше — у `loop()`. Антибрязкіт (ВП-5): перший фронт
запускає 50 мс тиші; якщо після неї кнопка ще натиснута — це одне натискання. Відскоки за ці 50 мс
забуваються, а брязкіт при відпусканні відсіюється, бо вхід тоді вже LOW:

```cpp
void IRAM_ATTR onButton() { edge = true; }
...
if (edge && !waiting) { waiting = true; edgeAt = now; }
if (waiting && now - edgeAt >= DEBOUNCE_MS) {
  waiting = false; edge = false;
  if (digitalRead(BUTTON) == HIGH) { presses++; setLevel((level + 1) % 4); }
}
```

`setLevel()` робить `ledcWrite(PWM_CH, LEVELS[level])` і друкує рівень (ВП-7):

```
Level: OFF (duty 0, 0%)
Press #1 -> LOW (duty 40, 16%)
Press #2 -> MID (duty 128, 50%)
Press #3 -> HIGH (duty 255, 100%)
Press #4 -> OFF (duty 0, 0%)
```

ШІМ змінює не напругу, а **частку часу**, коли ключ відкритий; при 5 кГц око бачить середню яскравість.
Ядро Arduino 2.x (`espressif32@^7`): `ledcSetup(канал, Гц, біт)` + `ledcAttachPin` + `ledcWrite(канал, …)`;
у ядрі 3.x — `ledcAttach(пін, Гц, біт)` і `ledcWrite(пін, …)`. `ledcWrite(…, 255)` ядро саме робить 100 %;
esp-hal так не вміє, тому в Rust 255 → 256.

## Етапи ТЗ: що міряти

| Етап | Прошивка | Що виміряти / побачити |
|---|---|---|
| 1. Живлення й розпіновка | — | шина MB-102 **4,75–5,25 В**; 2N2222 у режимі «діод»: B→E і B→C ≈ 0,6–0,7 В, E↔C — обрив. Пластиковий 2N2222A типово **E-B-C** (плаский бік до себе) — звірте з даташитом |
| 2. Керування з GPIO | `switch` | HIGH → LED світить, **U<sub>БЕ</sub> ≈ 0,6–0,8 В**; без спільної GND LED не світиться |
| 3. ШІМ | `sweep` | яскравість плавно росте; U колектор–GND (DC) падає, на паузі 255 — **≈ 0,1–0,2 В** |
| 4. Кнопка й ISR | `levels` | відео з натисканнями й Serial (вище) |
| «+» | `switch`, `softpwm` | U<sub>КЕ(нас)</sub> у фазі HIGH; програмний ШІМ проти LEDC |

## Рівень «+»: програмний ШІМ проти LEDC

`softpwm` — та сама кнопка, але вихід перемикає процесор: `now % 10 < duty * 10 / 255` → HIGH.
Записано аналізатором і розібрано [`tools/vcd_pwm.py`](tools/vcd_pwm.py)
([`results/pwm-compare-cpp.txt`](results/pwm-compare-cpp.txt); це запис у симуляції, на платі
перезаписати: PulseView → Export → VCD, канал GPIO5):

| | Частота | LOW = 40 | MID = 128 | Розкид періоду |
|---|---|---|---|---|
| LEDC (`levels`) | 5000 Гц | 15,6 % | 50,0 % | 0 мкс |
| `millis()` (`softpwm`) | 100 Гц | **10,0 %** | 50,0 % | 19–35 мкс |

![LEDC і програмний ШІМ на рівні LOW](docs/pwm-compare.png)

`millis()` рахує цілими мс, період 10 мс → лише 11 заповнень: 40/255 × 10 = 1,57 мс округлюється до 1 мс.
Для 256 кроків потрібен період 256 мс (≈ 4 Гц) — LED блимав би. Фронти «тремтять», бо настають на
першому проході `loop()` після межі мілісекунди, а будь-який `delay()` заморожує вихід. LEDC після одного
запису генерує сигнал сам і нічого не коштує процесору.

## Примітки

1. **Тест «зняти GND — LED гасне» може не спрацювати**, якщо MB-102 живиться від USB того самого ПК:
   «мінуси» вже з'єднані через комп'ютер. Для чесного тесту — окремий адаптер чи батарея.
2. Дріт GND знімають при вимкненому живленні, потім вмикають — так виконано обидві вимоги ТЗ.
3. «Антидребезг» — калька; українською — **антибрязкіт** (усунення брязкоту).
4. Яскравість нелінійна: око сприймає її приблизно логарифмічно, тож LOW = 16 % виглядає яскравішим,
   а MID і HIGH майже однакові. Рівномірніше — з гамма-корекцією (напр. 0 / 10 / 60 / 255).
5. Схеми згенеровано скриптами з [`docs/tools/`](docs/tools/).
