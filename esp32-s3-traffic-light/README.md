# ESP32-S3: «Світлофор» за ПДР України — Модуль 2, урок 28 (міні-проєкт)

Три LED працюють як світлофор із послідовністю сигналів за Правилами дорожнього руху України, а кнопка вмикає режим
нерегульованого перехрестя — жовтий миготливий. Машина станів у суперциклі: кожні 10 мс програма дивиться на час і
кнопку, `delay()` для відліку не використовується.

```bash
cd esp32-s3-traffic-light/cpp  && pio run -t upload && pio device monitor   # C, ESP-IDF: src/main.c
cd esp32-s3-traffic-light/rust && source ~/export-esp.sh && cargo run --release   # Rust, ESP-IDF: src/main.rs
```

## Сигнали

| Стан | Червоний | Жовтий | Зелений | Тривалість | Що означає |
|---|---|---|---|---|---|
| Зелений | | | ● | `GREEN_MS` 10 с | рух дозволено |
| Зелений миготливий | | | ◐ | `GREEN_BLINK_MS` 3 с, 3 блимання | дозволений час закінчується |
| Жовтий | | ● | | `YELLOW_MS` 3 с | рух заборонено, скоро зміна |
| Червоний | ● | | | `RED_MS` 10 с | рух заборонено |
| Червоний + жовтий | ● | ● | | `RED_YELLOW_MS` 2 с | скоро зелений, рух ще заборонено |
| Жовтий миготливий | | ◐ | | доки не натиснуть кнопку | нерегульоване перехрестя |

◐ — миготіння 1 Гц (`BLINK_MS` 500: 0,5 с світить, 0,5 с ні). Після червоного з жовтим цикл починається знову із
зеленого. Кнопка в звичайному режимі вмикає жовтий миготливий, у миготливому повертає світлофор на **червоний**:
після нерегульованого режиму всі спершу зупиняються.

Тривалості — макроси (у Rust константи) на початку файлу, їх легко змінити.

## Схема

```
GPIO15 ── 220 Ом ── LED червоний ── GND
GPIO16 ── 220 Ом ── LED жовтий ──── GND
GPIO17 ── 220 Ом ── LED зелений ─── GND
GPIO21 ── кнопка ── GND                     внутрішня підтяжка, резистор не потрібен
```

| Деталь | Шт. |
|---|---|
| YD-ESP32-S3 (N16R8), кабель USB-C у порт **USB** | 1 |
| LED червоний, жовтий, зелений | по 1 |
| резистор 220 Ом | 3 |
| тактова кнопка | 1 |
| макетка, дроти | — |

Довга ніжка LED (анод) — до резистора, коротка — на GND. Усі GND — на одну шину «−», з'єднану з GND плати.

## Як це працює

Стан і момент його початку зберігаються у двох змінних, а тривалість і наступний стан кожного сигналу — у двох
таблицях. Кожні 10 мс програма спершу перевіряє, чи не вийшов час поточного стану, і лише потім вмикає LED, тому між
сигналами не буває проміжного «кадру»:

```c
static const int64_t DURATION[] = {GREEN_MS, GREEN_BLINK_MS, YELLOW_MS, RED_MS, RED_YELLOW_MS, 0};
static const state_t NEXT[]     = {GREEN_BLINK, YELLOW_ON, RED_ON, RED_YELLOW, GREEN_ON, YELLOW_BLINK};

int64_t t = now_ms() - since;          // скільки триває поточний стан
if (DURATION[state] && t >= DURATION[state]) {
    go(NEXT[state]);                   // жовтий миготливий (0) чекає на кнопку
    t = 0;
}
bool blink = (t / BLINK_MS) % 2;       // 0, 1, 0, 1 … кожні 0,5 с
```

Миготіння теж рахується від початку стану, тому зелений блимає рівно тричі й переходить у жовтий без «обрізаного»
блимання. Кнопка опитується в тому самому суперциклі: брязкіт нашої кнопки коротший за крок 10 мс, це показали виміри
ДЗ 2.6 (`poll`: 0 відскоків на 22 натискання).

Кожна зміна стану друкується в Serial:

```
Світлофор за ПДР України. Кнопка: жовтий миготливий ↔ звичайний режим
[2000 мс] зелений
[12000 мс] зелений миготливий
[15000 мс] жовтий
[18000 мс] червоний
[28000 мс] червоний + жовтий
[30000 мс] зелений
```

Це очікування за кодом; на платі всі переходи зсунуті на ті самі 7 мс ([лог](results/serial-rust.txt)).

## Перевірка

| Перевірка | Що зробити | Правильний результат | Плата |
|---|---|---|---|
| Цикл | дивитися 2 цикли | зелений 10 с → миготливий 3 с → жовтий 3 с → червоний 10 с → червоний + жовтий 2 с | так, 2 цикли: переходи точно через 10,0 / 3,0 / 3,0 / 10,0 / 2,0 с, [лог](results/serial-rust.txt) |
| Зелений миготливий | рахувати блимання | рівно 3 | |
| Червоний + жовтий | дивитися | світять обидва, зелений ні | |
| Кнопка в циклі | натиснути будь-коли | одразу жовтий миготливий | |
| Кнопка в миготливому | натиснути ще раз | червоний, далі звичайний цикл | |

## C ↔ Rust

| | C (ESP-IDF 6.1) | Rust (esp-idf-hal, ESP-IDF 5.5) |
|---|---|---|
| Стани | `typedef enum` + `switch` | `enum State` + `match`, забутий стан не скомпілюється |
| Виводи | `gpio_config()`, `gpio_set_level()` | `PinDriver::output()`, `set_level()` |
| Кнопка | `.pull_up_en = GPIO_PULLUP_ENABLE`, `gpio_get_level()` | `PinDriver::input(…, Pull::Up)`, `is_low()` |
| Час | `esp_timer_get_time() / 1000` | `EspTaskTimerService::now()` |
| Крок суперциклу | `vTaskDelay(pdMS_TO_TICKS(10))` | `FreeRtos::delay_ms(10)` |
