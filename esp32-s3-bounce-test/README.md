# ESP32-S3: тест брязкоту кнопки з логічним аналізатором

Кнопка на GPIO21 і два «свідки» того самого сигналу: **переривання ESP32**, яке записує час кожного
фронту, і **логічний аналізатор** на тому ж проводі. Після кожного натискання й відпускання в Serial
з'являється звіт, який можна порівняти із записом аналізатора.

```bash
cd esp32-s3-bounce-test/cpp && pio run -e lab -t upload && pio device monitor        # C++: src/main.cpp
cd esp32-s3-bounce-test/cpp && pio run -e homework -t upload && pio device monitor   # код з умови ДЗ 1.5
cd esp32-s3-bounce-test/rust && cargo run --release                   # Rust: src/bin/lab.rs
cd esp32-s3-bounce-test/rust && cargo run --release --bin homework    # Rust: src/bin/homework.rs
```

`homework` — код з умови ДЗ модуля 1.5 без змін у логіці (лічильник `FALLING`), лише пін 16 → 21.

Конспект з анімаціями й справжніми даними цього стенду:
**[Брязкіт на стенді](https://grok-rs.github.io/platformio-projects/bounce-bench/)**.


## Як це працює

Обробник `CHANGE` лише записує `micros()` у масив — без `Serial`, бо переривання має бути коротким:

```cpp
void IRAM_ATTR onEdge() {
  uint32_t now = micros();
  if (edgeCount < MAX_EDGES) edgeTimes[edgeCount] = now;
  edgeCount = edgeCount + 1;
  lastEdgeUs = now;
  if (edgeCount == 2) digitalWrite(BOUNCE, HIGH);  // другий фронт = брязкіт
}
```

`loop()` чекає 50 мс тиші, на мить вимикає переривання (`noInterrupts()`), забирає масив і друкує:

```
PRESS   #1   edges=7   bounce=   812 us  shortest=4 us
        gaps us: 210 4 151 9 380 58
RELEASE #1   edges=1   bounce=     0 us  (clean, no bounce)
```

- `edges` — скільки фронтів побачило переривання (чиста подія = 1), `bounce` — від першого до
  останнього фронту, `shortest` — найкоротший інтервал, `gaps us` — перші 10 інтервалів.
- `GLITCH` — фронти були, а рівень не змінився (короткий імпульс без натискання).
- **Парність:** зміна рівня — це 1, 3, 5… фронтів. Якщо парність не сходиться, імпульс був
  коротший за реакцію ISR і фронт загубився → `[ISR missed >=1 edge - see analyzer]`.

## Logic 2

24 MS/s, запис кілька секунд. Тригер на Channel 1 (BOUNCE) rising — запис стартує лише на брязкіт.
Analyzers → Async Serial на Channel 2, 115200 — підписи `RELEASE#7 e=4 972us` (`MISSED`) на шкалі,
~50 мс правіше самої «гребінки».

## Результати стенду

Справжній запис 190 подій: [`docs/bench-11-40.serial.txt`](docs/bench-11-40.serial.txt) (перша версія
прошивки, формат рядків той самий).

- Натискання брязкотіло лише 1 раз із 91, відпускання — у 38 % (35 із 91), до 3.6 мс і 8 фронтів;
  у чверті подій ISR загубила фронт. Тригер варто ставити на **обидва** фронти.
- Аналізатор бачить більше фронтів, ніж ESP32: ISR стартує за кілька мкс, тому `shortest` рідко < 3–5 мкс,
  а аналізатор на 24 MS/s розрізняє ~42 нс.
- Нова кнопка — 0–1 мс брязкоту, стара — до 5–10 мс. Звідси програмний антибрязкіт 20–50 мс.
