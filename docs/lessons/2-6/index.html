04 Головні ідеї


    

      
Вікно живе між брязкотом і натисканням

      
Спершу числа. LMS дає діапазони від 2 мс до понад 100 мс, але без джерела. Перевірні дані скромніші: даташит Omron B3F обіцяє до 5 мс, Ганссл виміряв у середньому 1,6 мс, а наш стенд — медіану 0,18 мс і максимум 3,56 мс, якщо не рахувати двох аномалій, довших за 10 мс.

      
Вікно debounce має накрити брязкіт, але не з'їсти справжнє натискання. Пересуньте його й подивіться, де воно перестає працювати.

      
      
Головне20–50 мс — це не магія, а запас: у 5–15 разів більше за звичайний найдовший брязкіт нашої кнопки й менше за швидке натискання.

    


    

      
Час не знає, що сталося. Рівень знає

      
Завдання 2 з ДЗ фільтрує за часом: менше ніж 50 мс від попереднього переривання — ігноруємо. Брязкіт на самому натисканні справді зникає. Але подивіться, що приходить через 300 мс: кнопку відпускають, контакт тремтить, і в цьому тремтінні є спадаючий фронт. Для фільтра це нова подія, бо минуло вже 300 мс. У нашому записі такий фронт є в 35 із 91 відпускання.

      
Завдання 3 ставить інше запитання: не «скільки минуло», а «що зараз на вході». Переривання лише будить задачу. Вона чекає, поки все затихне, і дивиться на рівень: LOW — кнопку тримають, це натискання. HIGH — це було відпускання або завада.

      
vTaskDelay(pdMS_TO_TICKS(DEBOUNCE_MS));  // чекає лише ця задача, не весь чип

if (gpio_get_level(BUTTON) != 0) {  // уже HIGH: це був брязкіт відпускання або завада
    ignored++;
    continue;
}

      
ГоловнеФільтр за часом дивиться на годинник, а debounce за рівнем — на кнопку. Тому перший плутає відпускання з натисканням, а другий ні.

    


    

      
Машина станів: пам'ять замість очікування

      
Попередній спосіб чекає всередині задачі: поки він чекає, ця задача більше нічого не робить. Машина станів не чекає ніколи. Кожні 10 мс вона читає кнопку, дивиться, у якому стані була, вирішує, куди перейти, і одразу йде далі. Уся «пам'ять» — одна змінна state і час since.

Переривань тут немає зовсім, і це не лінощі: кнопку тисне людина, а опитування кожні 10 мс для неї миттєве. Зате код легко розширити: довге натискання, подвійне, комбінації. Спробуємо в розділі 05.

      
ГоловнеМашина станів запам'ятовує, де вона зараз, і тому ніколи не стоїть. loop() чи задача вільні для іншої роботи.

    


    

      
RC-фільтр: брязкіт гасне ще до входу

      
Попередні способи прибирають брязкіт програмою. Завдання 5 прибирає його залізом: конденсатор на вузлі кнопки не дає напрузі стрибнути миттєво. Коли контакт на мить розмикається, вузол починає заряджатися через підтяжку, але не встигає дійти до HIGH: контакт уже знову замкнувся.

      
Працює це лише тоді, коли стала часу τ = R·C порівнянна з паузами брязкоту. На схемі ДЗ заряд іде через R1, 10 кОм × 100 нФ = 1 мс, а рівень HIGH (0,75·VDD) настає через ≈ 1,39 τ. Розряд іде через R2 і кнопку: 100 Ом × 100 нФ = 10 мкс, тому натискання майже не запізнюється. Панель нижче дозволяє змінювати все це.

      
ГоловнеRC працює асиметрично: натискання майже миттєве, відпускання повільне. Саме це й потрібно, бо брязкоче в нас здебільшого відпускання.

Застереження. Між 0,25 і 0,75·VDD рівень не визначений, а гістерезису входів ESP32-S3 документи не вказують. Повільний фронт довго сидить у цій зоні, тому на переривання може прийти зайвий фронт саме там, де RC мав усе заспокоїти. Перевірте аналізатором, не вірте моделі на слово.

      

    


    

      Детальніше: чому «Спосіб 3» з LMS не найкращий
      
LMS називає «перериванням + таймером» код, де в ISR стоїть if (currentTime - lastInterruptTime > 50). Апаратного таймера там немає, лише millis(). Це той самий фільтр за часом, тільки всередині ISR, а отже, з тією самою бідою: спадаючий фронт відпускання проходить. Про це прямо сказано в очікуваному результаті завдання 2 з ДЗ 2.4: «все ще можливі спрацювання при відпусканні».

      
Є й дрібніша різниця: текст LMS обіцяє, що час оновлюється навіть для брязкоту, а в коді він оновлюється лише для прийнятого натискання. Наш time.c рахує від попереднього переривання, тож пачка фронтів, довша за вікно, теж не проб'є фільтр.

    

    

      Для допитливих: debounce у вебі й відео про React
      
Друге відео уроку — про веб. Слово те саме, ідея схожа, але світ інший: там не контакти, а події клавіатури чи прокрутки. Що переноситься: trailing debounce (виконати після паузи) — це наша «тиша» з уроку 2.4, а leading debounce (виконати на першій події, решту ігнорувати) — це наш time.c. Що не переноситься: setTimeout живе в черзі браузера, а не в ISR, і ніяких «спадаючих фронтів» там немає, тож проблему відпускання відео не зачіпає.

06 Розбираємо приклад: ESP-IDF і розрахунок

    
Домашнє завдання 2.6 — це завдання 2.4, але на ESP-IDF. Це той самий фреймворк Espressif, на якому стоїть Arduino-ESP32, тільки без обгортки. Є різниця у версіях: наші Arduino-проєкти спираються на ESP-IDF 4.4, а цей проєкт на 6.1, де старого driver/timer.h уже немає. Приклади для старих версій можуть не зібратися.

Новий прийом тут один: ISR не ставить прапорець, а будить задачу. Задача спить у xQueueReceive() і не витрачає процесор, а прокидається одразу, якщо ISR попросить перемикання:

    
static void IRAM_ATTR on_fall(void* arg) {
    int64_t t = esp_timer_get_time();
    BaseType_t woken = pdFALSE;
    xQueueSendFromISR(edges, &t, &woken);
    if (woken) portYIELD_FROM_ISR();
}

    
Пастка тіку. У чистому ESP-IDF тік FreeRTOS дорівнює 10 мс, а в Arduino 1 мс. pdMS_TO_TICKS() ділить націло, тож pdMS_TO_TICKS(5) за 100 Гц дає 0 тіків, і задача зовсім не спить. Тому в нашому проєкті sdkconfig.defaults ставить CONFIG_FREERTOS_HZ=1000.

07 Типові помилки

    

      

        
delay(50) у коді кнопки неправильний, бо зупиняє весь мікроконтролер і переривання.

        
На ESP32 delay() викликає vTaskDelay(): чекає лише ваша задача, а переривання й інші задачі працюють. Погано інше: поки loop() стоїть, він нічого більше не робить.

        
Поставте в loop() delay(2000), а в ISR лічильник. Натискайте під час затримки: лічильник росте.

      

      

        
Поставив фільтр на 50 мс, і брязкоту більше немає.

        
Зникає лише брязкіт одразу після натискання. Спадаючий фронт із брязкоту відпускання приходить через сотні мілісекунд і проходить вікно.

        
Лабораторія зверху: спосіб «За часом», натисніть «Наступне з фантомом».

      

      

        
Чим більше вікно, тим надійніше.

        
Більше вікно означає більшу затримку реакції, а натискання, коротші за вікно, будуть відкинуті. Коротше за вікно — це для програми взагалі не натискання.

        
Лабораторія: спосіб «За рівнем», тримання 40 мс, вікно 50 мс. Подивіться на «Пропущено».

      

      

        
Опитування — це завжди гірше за переривання.

        
Для кнопки навпаки: людина не помітить 10 мс, а опитування не отримує зливи фронтів. Завдання 4 з ДЗ прямо каже: найстабільніша поведінка.

        
Порівняйте рядки «Polling» і «Без debounce» у своїй таблиці завдання 6.

      

      

        
RC на 1 кОм і 100 нФ прибирає брязкіт 5–20 мс.

        
τ тут 100 мкс: у сотні разів менше за названий брязкіт. До того ж на схемі з LMS немає підтяжки, тому конденсатору нічим заряджатися.

        
Панель RC у розділі 04: кнопка «LMS» і паузи запису.

      

    

    
    

  


  
  

    
08 Схема і макетка

    
Кнопка між GPIO7 і GND з підтяжкою 10 кОм до 3,3 В. Підтяжка зовнішня і незмінна, як просить завдання, тому внутрішню в коді вимкнено. LED на GPIO15 через 220 Ом перемикається на кожну реакцію: на нього зручно дивитися і оком, і другим каналом аналізатора. GPIO35 із тексту уроку не беріть: на N16R8 він зайнятий PSRAM.

#include <stdio.h>
#include "driver/gpio.h"
#include "esp_attr.h"
#include "freertos/FreeRTOS.h"
#include "freertos/task.h"

// Завдання 1: переривання на FALLING лише рахує, debounce немає.
// Очікуємо: одне натискання дає кілька переривань, і при відпусканні вони теж бувають.
#define BUTTON GPIO_NUM_7   // кнопка на GND, підтяжка 10 кОм до 3V3
#define LED    GPIO_NUM_15  // LED через 220 Ом: перемикається на кожне переривання

static volatile uint32_t count = 0;  // пише ISR, читає app_main

static void IRAM_ATTR on_fall(void* arg) {
    count++;
}

void app_main(void) {
    gpio_config_t button = {.pin_bit_mask = 1ULL << BUTTON, .mode = GPIO_MODE_INPUT, .intr_type = GPIO_INTR_NEGEDGE};
    gpio_config(&button);
    gpio_config_t led = {.pin_bit_mask = 1ULL << LED, .mode = GPIO_MODE_OUTPUT};
    gpio_config(&led);
    gpio_install_isr_service(0);
    gpio_isr_handler_add(BUTTON, on_fall, NULL);

    printf("Завдання 1: лише переривання\n");
    uint32_t shown = 0;
    while (1) {
        if (count != shown) {
            shown = count;
            gpio_set_level(LED, shown & 1);
            printf("переривань: %lu\n", shown);
        }
        vTaskDelay(pdMS_TO_TICKS(10));
    }
}

    

    

      Код: завдання 2, src/time.c

#include <stdio.h>
#include "driver/gpio.h"
#include "esp_attr.h"
#include "esp_timer.h"
#include "freertos/FreeRTOS.h"
#include "freertos/queue.h"
#include "freertos/task.h"

// Завдання 2: debounce за часом. ISR лише кладе час переривання в чергу, а рішення приймає задача:
// менше ніж DEBOUNCE_US від попереднього переривання — ігноруємо.
// Очікуємо: хибних менше, але брязкіт відпускання все ще може дати зайве натискання.
#define BUTTON      GPIO_NUM_7   // кнопка на GND, підтяжка 10 кОм до 3V3
#define LED         GPIO_NUM_15  // LED через 220 Ом: перемикається на кожне прийняте натискання
#define DEBOUNCE_US 50000
#define QUIET_MS    200          // друкуємо підсумок, коли стало тихо

static QueueHandle_t edges;

static void IRAM_ATTR on_fall(void* arg) {
    int64_t t = esp_timer_get_time();
    BaseType_t woken = pdFALSE;
    xQueueSendFromISR(edges, &t, &woken);
    if (woken) portYIELD_FROM_ISR();
}

void app_main(void) {
    edges = xQueueCreate(64, sizeof(int64_t));
    gpio_config_t button = {.pin_bit_mask = 1ULL << BUTTON, .mode = GPIO_MODE_INPUT, .intr_type = GPIO_INTR_NEGEDGE};
    gpio_config(&button);
    gpio_config_t led = {.pin_bit_mask = 1ULL << LED, .mode = GPIO_MODE_OUTPUT};
    gpio_config(&led);
    gpio_install_isr_service(0);
    gpio_isr_handler_add(BUTTON, on_fall, NULL);

    printf("Завдання 2: debounce за часом, %d мс\n", DEBOUNCE_US / 1000);
    int64_t last = -DEBOUNCE_US, reaction = 0;
    uint32_t accepted = 0, ignored = 0;
    bool fresh = false;
    while (1) {
        int64_t t;
        if (xQueueReceive(edges, &t, pdMS_TO_TICKS(QUIET_MS)) != pdTRUE) {
            if (fresh) printf("прийнято: %lu, відкинуто: %lu, реакція: %ld мкс\n", accepted, ignored, (long)reaction);
            fresh = false;
            continue;
        }
        fresh = true;
        bool ok = t - last >= DEBOUNCE_US;
        last = t;  // рахуємо від попереднього переривання, не від прийнятого
        if (!ok) {
            ignored++;
            continue;
        }
        accepted++;
        gpio_set_level(LED, accepted & 1);
        reaction = esp_timer_get_time() - t;
    }
}

    

    

      Код: завдання 3, src/state.c

#include <stdio.h>
#include "driver/gpio.h"
#include "esp_attr.h"
#include "esp_timer.h"
#include "freertos/FreeRTOS.h"
#include "freertos/semphr.h"
#include "freertos/task.h"

// Завдання 3: debounce за рівнем. ISR лише сигналізує «подія», а задача чекає, поки брязкіт затихне,
// і приймає подію, тільки якщо кнопка досі натиснута. Відпускання нічого не робить.
// Очікуємо: рівно 1 реакція на 1 натискання.
#define BUTTON      GPIO_NUM_7   // кнопка на GND, підтяжка 10 кОм до 3V3
#define LED         GPIO_NUM_15  // LED через 220 Ом: перемикається на кожне прийняте натискання
#define DEBOUNCE_MS 50

static SemaphoreHandle_t event;
static volatile uint32_t edges = 0;  // скільки переривань було насправді

static void IRAM_ATTR on_fall(void* arg) {
    edges++;
    BaseType_t woken = pdFALSE;
    xSemaphoreGiveFromISR(event, &woken);
    if (woken) portYIELD_FROM_ISR();
}

void app_main(void) {
    event = xSemaphoreCreateBinary();
    gpio_config_t button = {.pin_bit_mask = 1ULL << BUTTON, .mode = GPIO_MODE_INPUT, .intr_type = GPIO_INTR_NEGEDGE};
    gpio_config(&button);
    gpio_config_t led = {.pin_bit_mask = 1ULL << LED, .mode = GPIO_MODE_OUTPUT};
    gpio_config(&led);
    gpio_install_isr_service(0);
    gpio_isr_handler_add(BUTTON, on_fall, NULL);

    printf("Завдання 3: debounce за рівнем, %d мс\n", DEBOUNCE_MS);
    uint32_t presses = 0, ignored = 0;
    while (1) {
        xSemaphoreTake(event, portMAX_DELAY);
        int64_t t0 = esp_timer_get_time();
        vTaskDelay(pdMS_TO_TICKS(DEBOUNCE_MS));  // чекає лише ця задача, не весь чип

        if (gpio_get_level(BUTTON) != 0) {  // уже HIGH: це був брязкіт відпускання або завада
            ignored++;
            continue;
        }

        presses++;
        gpio_set_level(LED, presses & 1);
        long reaction = esp_timer_get_time() - t0;
        printf("натискань: %lu, відкинуто подій: %lu, переривань: %lu, реакція: %ld мкс\n",
               presses, ignored, edges, reaction);

        while (gpio_get_level(BUTTON) == 0) vTaskDelay(pdMS_TO_TICKS(10));  // довге утримання — одна реакція
        vTaskDelay(pdMS_TO_TICKS(DEBOUNCE_MS));                             // брязкіт відпускання затихає
        xSemaphoreTake(event, 0);                                           // і його подію теж прибираємо
    }
}

#include <stdio.h>
#include "driver/gpio.h"
#include "esp_timer.h"
#include "freertos/FreeRTOS.h"
#include "freertos/task.h"

// Завдання 4: без переривань. Кожні POLL_MS читаємо кнопку, debounce — машина станів
// IDLE → PRESSED → HELD → RELEASE → IDLE. Рівень мусить протриматися STABLE_US.
// Очікуємо: найстабільніша поведінка, реакція трохи більша (STABLE_US + період опитування).
#define BUTTON    GPIO_NUM_7   // кнопка на GND, підтяжка 10 кОм до 3V3
#define LED       GPIO_NUM_15  // LED через 220 Ом: перемикається на кожне прийняте натискання
#define POLL_MS   10
#define STABLE_US 50000
#define LONG_US   2000000      // довше — довге натискання

typedef enum { IDLE, PRESSED, HELD, RELEASE } state_t;

void app_main(void) {
    gpio_config_t button = {.pin_bit_mask = 1ULL << BUTTON, .mode = GPIO_MODE_INPUT};  // без intr_type
    gpio_config(&button);
    gpio_config_t led = {.pin_bit_mask = 1ULL << LED, .mode = GPIO_MODE_OUTPUT};
    gpio_config(&led);

    printf("Завдання 4: опитування кожні %d мс + машина станів\n", POLL_MS);
    state_t state = IDLE;
    int64_t since = 0, pressed_at = 0;
    uint32_t presses = 0, bounces = 0;
    TickType_t wake = xTaskGetTickCount();
    while (1) {
        vTaskDelayUntil(&wake, pdMS_TO_TICKS(POLL_MS));  // рівно кожні POLL_MS, скільки б не тривав код нижче
        bool down = gpio_get_level(BUTTON) == 0;
        int64_t now = esp_timer_get_time();

        switch (state) {
            case IDLE:
                if (down) { state = PRESSED; since = now; }
                break;
            case PRESSED:
                if (!down) { state = IDLE; bounces++; }  // відскочило: це ще брязкіт
                else if (now - since >= STABLE_US) {
                    state = HELD;
                    pressed_at = since;
                    presses++;
                    gpio_set_level(LED, presses & 1);
                    printf("натискань: %lu, відскоків: %lu, реакція: %ld мкс\n", presses, bounces, (long)(now - since));
                }
                break;
            case HELD:
                if (!down) { state = RELEASE; since = now; }
                break;
            case RELEASE:
                if (down) { state = HELD; bounces++; }  // брязкіт відпускання
                else if (now - since >= STABLE_US) {
                    state = IDLE;
                    printf("%s натискання\n", since - pressed_at < LONG_US ? "коротке" : "довге");
                }
                break;
        }
    }
}

12 Командний виклик

    

      Командний виклик
      
Одна кнопка, три жести

      

        
Мета
Одна кнопка на машині станів розрізняє три жести: коротке натискання перемикає LED, довге (понад 2 с) вмикає режим миготіння, подвійне змінює швидкість. Без delay(), без жодної хибної реакції.

        
Здати
Код, діаграма станів і 20-секундне відео всіх трьох жестів.

        
Ролі
  • Збирач: схема й машина станів;
  • Вимірювач: по 20 спроб кожного жесту, таблиця «розпізнано / переплутано»;
  • Доповідач: допис у «Командні виклики»;
  • Скептик: шукає послідовність натискань, яка ламає машину станів іншої команди.

        
Критерії
4 критерії по 0–2 бали
Кожен 0–2 бали. Усі три жести розпізнаються: 2 — завжди, 1 — через раз, 0 — ні. Фантоми за 60 спроб: 2 — жодного, 1 — 1–2, 0 — більше. Діаграма збігається з кодом: 2 — так, 1 — майже, 0 — ні. Без delay() в обробці кнопки: 2 — так, 0 — ні.

        
Ускладнення
Зробіть те саме на ESP-IDF: окрема задача кнопки шле жести в чергу FreeRTOS.
